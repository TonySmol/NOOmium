## 1. Критические (1)

### F-01 · КРИТИЧЕСКИЙ · Баг · PWA · manifest.json:4, 40, 47
**Манифест в кодировке CP1251 вместо UTF-8 — моджибейк в install-UI**

**Описание:** Поля description и labels скриншотов записаны байтами CP1251. Спека W3C App Manifest / RFC 8259 требует UTF-8: браузер декодирует как UTF-8, и пользователь видит «Ñîöñåòü ñìûñëîâ…» в диалоге установки и в карточке приложения. Остальные файлы проекта — валидный UTF-8 с BOM, манифест выбивается (CRLF, без BOM).

**Доказательство:** hex description = d1 ee f6 f1 e5 f2 fc…; latin1→cp1251 восстанавливает «Соцсеть смыслов: мысли ищутся по значению, а не по словам».

**Как чинить:** Пересохранить manifest.json в UTF-8 (плюс LF для единообразия).

## 2. Высокие (11)

### F-02 · ВЫСОКИЙ · Безопасность · NET · app.js:2585–2594
**Приватный ключ Nostr лежит в localStorage открытым текстом**

**Описание:** saveKey() пишет hex-SK напрямую в localStorage под ключом 'noomium:sk'. Любой успешный XSS, браузерное расширение или общий ПК = полная кража идентичности. Смягчение (ncryptsec-обёртка) существует только как опция экспорта, дефолт — plaintext.

**Доказательство:** localStorage.setItem(SK_KEY, Array.from(key).map(b => …padStart(2,'0')).join('')) — без шифрования.

**Как чинить:** Хранить ключ в зашифрованном виде (NIP-49 с паролем / WebCrypto non-extractable key + wrap), plaintext — только в памяти сессии.

### F-03 · ВЫСОКИЙ · Безопасность · NET · app.js:3868–3888
**fetchOlder подписывается на релей напрямую, минуя верификацию подписей**

**Описание:** Все обычные подписки идут через nostr-tools SimplePool, который верифицирует подписи входящих событий. fetchOlder («слой вглубь» истории) вызывает ensureRelay(url).then(relay => relay.subscribe(…)) — прямая подписка БЕЗ верификации. Злонамеренный релей может подсунуть сфабрикованные каноны прямо в зеркало и ленту.

**Доказательство:** const sub = relay.subscribe([{ kinds:[kCanon()], '#t':[room()], since, until, limit }], { onevent: ev => { … onEvent(ev); } … }) — без verifyEvent.

**Как чинить:** Прогонять события через verifyEvent() перед onEvent, или использовать pool.querySync для истории.

### F-04 · ВЫСОКИЙ · Безопасность · DOMAIN · app.js:8289, 8303 + 5457–5461
**Экспорт «с ключом» молча кладёт голый nsec в JSON без шифрования**

**Описание:** Поле пароля в UI показывается только если canWrapKey()===true. Когда NIP-49 недоступен (старый браузер), getWrappedKey('') падает в fallback и возвращает RAW nsec, который уезжает в файл архива. Пользователь не получает никакого предупреждения, что файл содержит открытый ключ — hint 'account.export.withkey.hint' об этом не говорит.

**Доказательство:** exportArchive → getWrappedKey(keyPassword): const nsec = await Crypto.encodeNsec(sk); if (nsec) { Logger.warn(...); return nsec; } → archive.ncryptsec = …

**Как чинить:** Блокировать экспорт ключа при недоступном NIP-49 либо явно предупреждать в UI, что ключ будет в открытом виде.

### F-05 · ВЫСОКИЙ · Баг · AI · app.js:2073
**@huggingface/transformers@latest — незакреплённая версия с CDN**

### F-06 · ВЫСОКИЙ · Баг · DOMAIN · app.js:4522–4553
**Notes.backfill — потеря пользовательских правок (lost update)**

**Описание:** backfill делает снимок DB.allNotes() ДО цикла, для каждой заметки ждёт Embedder.embed (окно в секунды при N заметок), затем пишет СТАРЫЙ объект через DB.putNote без перечитывания и сверки версии. **Доказательство:** 4525 allNotes → 4535 await embed → 4543 putNote(n) без re-read; DB.putNote — безусловный put; edit() пишет конкурентно; Boot дёргает backfill по ai:ready (9789).

### F-09 · ВЫСОКИЙ · Баг · SW · sw.js:36–64
**Install глотает отказ precache — офлайн-режим деградирует молча**

### F-13 · СРЕДНИЙ · Баг · DATA · app.js:1958–1961
**evictMirror: компаратор возвращает NaN — порядок эвикции произвольный**

**Описание:** score для записей без lastShownStamp = Infinity*1e10 + ts = Infinity. Сравнение двух «никогда не показанных»: Infinity - Infinity = NaN → трактуется как 0 → сортировка не работает, порядок остаётся от getAll() (по uid). Докомментарий «LRU, потом ts» и лог «свежий фонд цел» фактически нарушены: свежеполученные записи эвиктятся наравне со старыми. Усугубляется: decideUpsert для tombstone не зовёт borrowMissing — lastShownStamp теряется при удалении→воскрешении.

**Доказательство:** const score = m => (m.lastShownStamp ? now - m.lastShownStamp : Infinity) * 1e10 + (m.ts || …); sorted.sort((a,b) => score(b) - score(a)).

**Как чинить:** Использовать флаг вместо Infinity (например lastShownStamp||0 → сортировать по паре [never, ts]).
